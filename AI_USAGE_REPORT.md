## Detailed Project & AI Usage Breakdown

### 1. What is CampusCare?

In most colleges, when students have questions about fees, attendance, ID cards, or certificates, they have to send emails, make phone calls, or stand in line outside administrative offices. Requests often get delayed or lost.

**CampusCare** solves this by giving the college a single, organized website:
- **Students** can submit a ticket, select a category and priority, track its progress, and chat with staff.
- **Support Staff** can see tickets assigned to their department, answer students publicly, write private internal notes to other staff, and resolve tickets.
- **College Administrators** can see an overview dashboard, check how long tickets take to resolve, spot overdue tickets, and balance staff workloads.

### 4. Important Problems Encountered and How They Were Solved

During development, we did not blindly accept AI output. We ran the code, tested it, found problems, and fixed them:

#### 1. Windows PowerShell command chaining
- **The Problem:** The AI generated a script using `npm install A && npm install B`. On Windows PowerShell, `&&` is not supported in older versions, and the command stopped.
- **The Fix:** Changed the separator to `;` and configured `concurrently` in `package.json` so one command starts both the backend and the frontend cleanly.

#### 2. Downloading CSV files in the browser
- **The Problem:** We wanted administrators to be able to download a spreadsheet (CSV) of all tickets. The backend required a secret login header. But when a user clicks a normal download link (`<a href="...">`), the web browser does not attach custom headers, causing a `401 Unauthorized` error.
- **The Fix:** Updated the backend security code (`server/auth.js`) so it also accepts the login token in the web address (`?token=...`). Now, clicking the "Export CSV" button downloads the file immediately.

#### 3. Protecting Private Staff Notes
- **The Problem:** Staff members need to write internal notes to each other (e.g., checking bank records) that students should never see. We needed to ensure no student could see these notes even if they opened their browser developer tools.
- **The Fix:** Implemented a rule directly in the database query: if the logged-in user is a student, the server never sends internal notes over the network. Only public replies are returned.

#### 4. Requiring a Resolution Summary
- **The Problem:** The SRS requires that staff cannot mark a ticket as "Resolved" without explaining how it was solved.
- **The Fix:** Both the website modal and the backend API block the resolution if the summary is empty or too short.
